# Выкладка на хостинг

Магазин статический: 59 готовых HTML-файлов, никакого рантайма. Ни Node на
сервере, ни переменных окружения, ни сборки на хосте не нужно — нужен только
веб-сервер, раздающий файлы.

## Перед первой выкладкой

**Ничего не отправляется.** Корзина, заказ, вход и письмо живут в `localStorage`
браузера. Посетитель видит «заказ принят», а заказ остаётся у него же в браузере.
Пока бэкенд не подключён, боевая выкладка собирает заказы в никуда. Точки врезки
три и названы в `CLAUDE.md`: `addOrder` в `orders.ts`, `signIn` в `session.ts`,
обработчики `submit` в `forms.ts`.

**Поиск работает целиком в браузере.** Форма в шапке ведёт на `/search?q=…`, а
ищет страница по тем же 38 товарам, что уже вшиты в сборку. Наружу запросы
покупателей не уходят, и серверный поиск для выкладки не нужен.

**`public/og-image.png` в репозитории нет**, а ссылка на него стоит в мета-тегах.
Без файла превью в мессенджерах будет пустым. Размер 1200×630, разбор — в
`docs/adr/0005-seo-metadata-and-indexing.md`.

**Домен вписан в сборку константой** (`site` в `astro.config.mjs`), и от него
считаются `canonical`, Open Graph и карта сайта. Второе место — `Sitemap:` в
`public/robots.txt`. Сменить домен правкой на сервере нельзя, только пересборкой;
сейчас там стоит заглушка `https://device.example`.

## Сборка

Зависимости ставятся **только Yarn**. `npm install` при наличии `yarn.lock`
перепишет его под себя и сломает установку у коллег на других платформах — почему
именно, разобрано в `CLAUDE.md`.

```
yarn install --frozen-lockfile
yarn build          # astro check && astro build
```

На выходе — папка `dist`. Source maps не генерируются. Заливается **содержимое**
`dist`, а не сама папка: корень сайта — `dist/index.html`.

Страниц 59: `index.html`, `catalog` с шестью разделами, 38 товаров в `product/`,
четыре производителя в `brand/`, плюс `cart`, `compare`, `profile`, `login`,
`logout`, `restore`, `search`, `about` и `404`. Каждая — папка со своим
`index.html`; исключение — `404.html`, его хостинг ищет по имени файла.

## Сжатие

Сжимать: `.html`, `.css`, `.js`, `.svg`, `.xml`, `.txt`.

Не сжимать: `.webp`, `.avif`, `.png`, `.jpg`, `.woff2` — они уже сжаты, повторный
проход только тратит процессор.

Страницы корзины и сравнения заметно тяжелее остальных: обе держат в разметке все
38 товаров скрытыми (разбор — `docs/adr/0008-client-state.md`). Под gzip это почти
не видно, без него — видно сразу.

## Заголовки кэша

Всё в `/_astro/` названо по хешу содержимого, включая шрифты, — эти файлы можно
кэшировать вечно. HTML кэшировать нельзя: иначе вернувшийся посетитель не увидит
новую вёрстку.

| Что                             | `Cache-Control`                       |
| ------------------------------- | ------------------------------------- |
| `/_astro/*`                     | `public, max-age=31536000, immutable` |
| любой `*.html`                  | `no-cache`                            |
| `/og-image.png`, `/favicon.svg` | `public, max-age=3600`                |
| `/robots.txt`, `/sitemap*.xml`  | `public, max-age=3600`                |

`og-image.png` стоит отдельного внимания: имя у него без хеша, а мессенджеры
держат превью в своём кэше долго. После замены картинки её придётся протолкнуть
через отладчики WhatsApp и Telegram вручную.

## MIME-типы

Astro раскладывает картинки в `.avif` и `.webp`. Старые сборки nginx про avif не
знают и отдают `application/octet-stream`. Проверить, что в `mime.types` есть:

`image/avif`, `image/webp`, `font/woff2`, `image/svg+xml`, `application/xml`.

Если включён `X-Content-Type-Options: nosniff`, это становится критичным: с ним
неверный тип у модульного `.js` даёт белую страницу вместо сайта.

## Домен и протокол

`canonical`, `og:url` и карта сайта содержат абсолютный адрес из `site`. Нужны
постоянные редиректы на этот вид:

- `http://` → `https://`
- `www.<домен>` → `<домен>`

Без них поисковик получит дубли страницы, а превью в мессенджерах будут вести на
неканоничный адрес.

## SPA-фолбэк не включать

Страницы статические и все лежат на диске. Настраивать «любой путь →
`index.html`» не надо: такой фолбэк отдаёт 200 на любой мусорный URL, и в индекс
лезут дубли. Несуществующий путь должен отвечать 404.

```nginx
root /var/www/device/dist;
index index.html;

location / {
    try_files $uri $uri/ $uri/index.html =404;
}

location /_astro/ {
    add_header Cache-Control "public, max-age=31536000, immutable";
}

location ~* \.html$ {
    add_header Cache-Control "no-cache";
}
```

`$uri/index.html` в `try_files` обязателен: адреса вида `/catalog/monopods` — это
папки, и без него они дадут 404.

## Порядок выкладки

Сначала `_astro` и остальная статика, затем HTML — тогда не возникнет окна, в
котором свежая страница просит ещё не залитые чанки.

Старую папку `_astro` в тот же момент не стирать: у посетителя с открытой
вкладкой догрузка чанков должна пережить деплой. Достаточно удалить её со
следующим релизом.

## Проверка после заливки

```
curl -I https://<домен>/                          # 200, text/html, no-cache
curl -I https://<домен>/catalog/monopods/         # 200
curl -I https://<домен>/product/giant-selfie-stick/
curl -I https://<домен>/robots.txt                # 200
curl -I https://<домен>/sitemap-index.xml
curl -I https://<домен>/og-image.png              # 200, image/png
curl -I https://<домен>/такого-нет               # 404
```

Плюс один прогон глазами: положить товар в корзину, оформить, зайти в кабинет.
Если `localStorage` заблокирован политикой браузера, всё это молча не работает —
и ловится только руками.
