# Каталог считается на сервере, а сайт разделён с API

Магазину заказана серверная часть: заказ должен доходить до базы, а фильтр,
сортировка, страницы и поиск — считаться в SQL, а не в браузере. Это решение
отменяет главное свойство проекта — «59 файлов и никакого рантайма», — поэтому
оно и записано.

## Что решено

Проектов становится два. `device` остаётся Astro-приложением и переходит на SSR
целиком (адаптер `node`). `device-api` — отдельный репозиторий: Express на
TypeScript, Postgres, Prisma. Браузер видит один домен: `/` уходит в Astro,
`/api` — в Express, `/uploads` — в фотографии товаров.

Astro в базу не ходит. Страница просит данные у Express по HTTP, как это делал бы
любой другой клиент.

## Почему не иначе

**Почему не гибрид — SSR только у каталога и поиска.** Такой вариант сохранил бы
пятьдесят страниц файлами и попиксельную приёмку в нынешнем виде. Отклонён ради
одного правила вместо двух: «страница строится на запрос» проще держать в голове,
чем список исключений, который придётся сверять при каждой новой странице.

**Почему не клиентская отрисовка каталога.** Сайт остался бы чистой статикой, а
плитки рисовал бы JS после ответа API. Отклонено: страница каталога выпала бы из
индекса, а первый экран приезжал бы пустым.

**Почему Astro не ходит в Postgres напрямую.** Один хоп вместо двух — но тогда
логика выдачи живёт в двух местах либо Express остаётся только под админку. Это
ровно то, чего заказ не предполагал.

**Почему один домен, а не `api.device.ru`.** Корзина переезжает на сервер, значит
нужна cookie. Между доменами это `SameSite=None; Secure`, CORS с `credentials` и
неработающая локальная разработка без https. При одном домене всего этого нет.

**Почему Prisma, а не Kysely или голый `pg`.** Узнаваемость и миграции из коробки
перевесили видимый SQL. Решение принято с открытыми глазами: в коде будет виден
DSL Prisma, а не запросы.

## Чем оплачено

- `docs/deploy.md` переписывается целиком: вместо раздачи файлов — Node-процесс,
  Postgres, миграции и порядок запуска.
- Приёмка снимками требует поднятой связки. Браузерные спеки поэтому переводятся
  на перехват `/api` с фикстурами, а настоящая база проверяется отдельными
  интеграционными тестами в репозитории API.
- Сборка перестаёт быть самодостаточной: `astro build` больше не доказывает, что
  сайт работает.
- Появляется единая точка отказа. Ответ на неё — страница «магазин недоступен» с
  кодом 503 на вёрстке существующей 404.
- Правило «вход ничего не защищает» отменяется вторым этапом: кабинет читает
  заказы с сервера, а значит покупателя надо отличать по-настоящему.

## Что осталось прежним

Состояние каталога по-прежнему живёт в адресе: клик по фильтру пишет
`replaceState` и перерисовывает список ответом API, а не перезагружает страницу.
Сцена фильтрации из ADR 0009 остаётся живой — призраки уходят сразу, новые
карточки въезжают по ответу.

Разделов по-прежнему шесть, и в базу они не едут: список закрыт глоссарием.
Сервер знает их как `slug` и сверяет по списку в OpenAPI.
