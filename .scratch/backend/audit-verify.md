# Проверка исправлений по ревизии

# Итог проверки исправлений по ревизии

## Закрыто полностью (оба агента — CLOSED)

**Фронт, страница 503 и клики:**

- Шапка и подвал больше не роняют страницу: `cartOf`/`meOf` ловят отказ (`src/server/api.ts:17,20`).
- Клик по вложенным элементам кнопки: делегирование через `closest` в `cart.ts`/`compare.ts`.
- Чужие клики и двойные срабатывания: по одному вызову `initCartControls`/`initCompareControls`, призраки сцены обезврежены, `stopPropagation` нигде нет.
- Клавиатура: обе кнопки — нативные `<button>`, Enter/Space работают.

**API, журнал и сессии:**

- Заголовки ответа не пишутся в журнал: `res`-сериализатор отдаёт только `statusCode`, стоит и на pino, и на pinoHttp; закрыто спекой.
- Сессии не заводятся ради отказа: `openSession` только в POST /items, остальные ручки отдают EMPTY.
- Прежняя сессия при входе закрывается после `mergeCarts` — корзина гостя не уезжает каскадом.
- Битая cookie ловится во всех семи местах чтения (единственный читатель — `keyFrom`).
- Заглушка `DUMMY_HASH`: те же параметры scrypt, обе ветки считают `ok` до проверки, время не расходится.

**Корзина:**

- Очередь: снимок сервера не затирает свежий клик (`flying`), закрыто спекой `tests/cart.spec.ts`.
- Ошибка в середине очереди не обгоняет следующие операции, unhandled rejection не возникает.
- Перенос старого `localStorage` не задваивает: ключ удаляется до отправки.
- Двойное оформление даёт 409, а не 500 (`deleteMany` + `gone.count === 0`).

**База и документы:**

- Триграммный индекс восстановлен и объявлен в `schema.prisma` — следующий diff его не снесёт.
- Коллация `kind` и три CHECK целы; появились пять индексов под внешние ключи (продублированы в PSL).
- Тела всех POST/PATCH описаны в OpenAPI (7 из 7; у `/logout` и `/cancel` тел нет).
- ADR 0003, 0007, 0008 помечены статусом; `CONTEXT.md` больше не противоречит себе про корзину и сравнение.

## Закрыто частично или не закрыто

**Страница 503**

- HTTP 500 от API маскируется под 503 «зайдите позже» с `Retry-After` — `500.astro` так и не заведён. Под ту же гребёнку попадают 502/504.
- Падение рендера самой 503 не подстраховано: второго `try` нет, уйдёт голое «Internal server error».
- В `astro dev` отключение стриминга не действует (опция адаптера) — там дефект воспроизводится как раньше. Нигде не записано.
- Спек на 503 нет ни одной: `grep 503` по `tests/` пуст. Регрессию поймать нечем.

**Корзина**

- Начальная загрузка и `refresh()` идут мимо очереди — устаревший снимок затирает свежий результат (замечание ревизии не снято).
- `flying` может застрять: нет таймаутов у `fetch`; исключение слушателя уменьшает счётчик дважды.
- Две вкладки и bfcache: слушателей `storage`/`pageshow` нет, `set` шлёт абсолютное количество — «+» во второй вкладке воскрешает удалённый товар (исправленным не заявлялось).
- Первая отрисовка: при отказе первого GET `known` остаётся `false` навсегда, `count()=0`, оформление молча мертво; клик до первого снимка стирает отрисованные строки.
- Перенос `localStorage`: прерванный теряет непереехавшие строки; отвергнутые 404/400 переотправляются вечно, каждый раз откладывая первый снимок.
- Двойной клик «Оформить» на клиенте не заблокирован; `expected` берётся из оптимистичного итога — законная покупка ловит 409.
- `locked` в `orders/service.ts` — обычный `findUnique` без FOR UPDATE, окно сузилось, но не закрыто.
- PATCH/DELETE без cookie отдают 200 EMPTY — протухшая сессия неотличима от пустой корзины; спек на них нет.

**Аккаунты**

- `verifyPassword` не сверяет разобранные параметры и длину ключа с константами: вырожденный хеш принимает любой пароль (проверено запуском node обоими агентами).
- Лимитер: основной сценарий отбивается, но IP-часть ключа бесполезна, у `/reset` общее ведро, перебора по многим адресам нет вовсе, Map без потолка, окно фиксированное.
- Сброс пароля: CAS вынесен за транзакцию; `askReset` не гасит прежние ссылки; спека про просрочку тавтологична и ничего не проверяет.
- Перечисление адресов осталось на `/register` (409) и `/restore` (время ответа и 500 при отказе SMTP).

**Контракт и документы**

- `errorSchema.code` без `unauthorized` и `too_many_requests`: документированные 401 недостижимы, 429 не описан. README и OpenAPI теперь противоречат друг другу.
- Тела сериализуются с `io: 'output'` — поля с `.default()` выходят обязательными, приводимые входы не показаны.
- `RestoreBody` не выведен из схемы, `ApiFailure` по-прежнему руками.
- Сверки «перегенерируй — diff пуст» нет ни в package.json, ни в husky, ни в CI (каталога `.github` нет).
- Мелочи контракта не тронуты: нет `security` у операций, `$ref` не используется, 500 не описан, 422 у PATCH недостижим, 400 у `/cancel` не описан.
- Две папки миграций с именем `fk_indexes`, SQL только во второй; на накатанном стенде это упрётся в контрольную сумму или в «index already exists».
- `docs/tests.md`: обещанного описания расхождения семантики поиска НЕТ, ложно-зелёные `toHaveCount` остались, два стухших места (`astro preview`, `storage` между вкладками) не поправлены.
- README API: таблица адресов так и на четырёх строках из восемнадцати, `DB_PORT` дважды.
- `deploy.md` противоречит сам себе про `/api` и кэш; `SITE_URL` не назван вовсе.
- `17-audit-fixes.md` расходится с кодом в двух утверждениях (описание расхождения поиска, «все адреса» в README) и наполовину в третьем.

## Регрессии, появившиеся из-за правок

Обоими агентами подтверждены:

1. **`src/pages/search.astro` (major)** — поиск глотает любую ошибку API и отвечает 200 «нашлось 0 товаров» вместо 503. Ревизия просила ловить только 400; отчёт о правках утверждает обратное тому, что в коде.
2. **`src/scripts/catalog.ts` (major)** — `fill()` не восстанавливает подпись и `aria-pressed` кнопки сравнения. Именно после появления делегирования кнопка стала живой, и на дорисованных карточках она обещает добавить, а убирает.
3. **`src/middleware.ts` (minor)** — охранник `if (path === DOWN) return next()` отправляет прямой запрос `/503` мимо блока заголовков кэша: персональная страница уходит с 200, без `Cache-Control` и `Vary: Cookie`.
4. **`src/middleware.ts` (minor)** — `private, no-store` вешается и на `/uploads/`, перетирая часовой кэш картинок от API.
5. **`src/scripts/forms.ts` (minor)** — ключ `login` больше никто не пишет, а `storage-move` его удаляет: подстановка в форме входа мертва навсегда, до первого запуска остаётся окно с подстановкой имени в поле e-mail.
6. **`src/middleware.ts` (nit)** — ответ 503 пересобирается и теряет заголовки переписанного ответа (скептик сузил: cookie через `Astro.cookies` выживают, пропадут записанные прямо в `Astro.response.headers`).
7. **Документы** — полный список кодов в README при неполном в `errorSchema` создал новое расхождение между двумя документами одного репозитория.

## Новые проблемы, подтверждённые обоими агентами

Критичные и крупные:

- `verifyPassword` без сверки параметров — обход входа вырожденным хешем; невозможный N даёт 500 вместо 401.
- `trust proxy` не включён при SSR-прокси — IP в ключе лимитера бесполезен.
- Общее ведро `ip:` у `/api/auth/reset` — блокируется всем (скептик: ведро общее для всех четырёх ручек, чему хватает пустого тела на `/login`).
- `/api/auth/restore` перечисляет адреса по времени ответа и по 500 при отказе SMTP — сводит на нет правку с `DUMMY_HASH`.
- Тавтологичная спека просрочки ссылки: уберёшь проверку из `applyReset` — останется зелёной.
- `io: 'output'` для тел запросов в OpenAPI.
- `errorSchema` без двух кодов.
- Пустая миграция-двойник `20260918110000_fk_indexes`.
- Противоречие в `deploy.md` про `/api` и кэш — риск «кэш отдаёт чужую корзину» для API открыт.
- Нет таймаутов у `fetch` во фронте (скептик уточнил: undici даёт 300 с и отказ всё-таки опознаётся как 503, но явный `AbortSignal.timeout` дал бы `TimeoutError` и 500).
- Начальная загрузка/`refresh` мимо очереди; `expected` из оптимистичного итога; `known=false` навсегда при отказе первого GET.

Помельче: клик до первого снимка стирает корзину; потеря строк при прерванном переносе; две сессии при параллельных POST без cookie; `Map` лимитера без потолка; CAS за транзакцией; `askReset` не гасит прежние ссылки; `/register` перечисляет адреса; фиксированное окно лимитера; `sid=` уходит пустой строкой в базу; двойной декремент `flying`; `locked` без FOR UPDATE; `DB_PORT` дважды; вклейки в ADR 0009 и CLAUDE.md.

**Только у скептика (вторым агентом не проверялось, но доказательство приведено построчно):**

- **Критично:** `error-handler.ts:55` пишет `{ err }` для SyntaxError от body-parser, а тот несёт сырое тело запроса перечислимым полем `body` — **пароль и почта уходят в журнал открытым текстом** при чуть битом JSON на `/login`. `redact` описан по `req`/`res` и этот путь не закрывает. Это ровно тот пункт, который первый агент пометил CLOSED.
- Гонка двух входов в один аккаунт → P2002 → 500 (`cart/service.ts`, ветка `mine === null`).
- `keyFrom` возвращает первую пару `sid` — протухший дубль навсегда затеняет живую cookie.
- `SITE_URL` не назван в `deploy.md` и необязателен в README — в бою письма уйдут на localhost без единой ошибки при старте.
- 489-строчный рукописный `mock-api.mjs` повторяет контракт и ничем не сверяется — браузерные спеки зелены на ложных числах.
- `hashPassword` считается до CAS; вторая рукописная копия списка кодов в `catalog/schemas.ts`.

## Где агенты разошлись

1. **Утечка в журнал через `err`.** Проверяющий — CLOSED, скептик — PARTIAL с живым путём. **Сильнее скептик:** он привёл цепочку по исходникам (`body-parser/lib/read.js:164-166` → `http-errors/index.js:98-100` → `pino-std-serializers/lib/err.js:28-38`), проверяющий же перебрал только `details`, `err.config` и стартовые логи. Это самая серьёзная находка всей проверки.
2. **Стриминг.** Проверяющий — CLOSED, скептик — PARTIAL. **Сильнее скептик:** `createAstroServerApp.js:42` передаёт `streaming=true` захардкоженно, опция адаптера в dev не доезжает. Фактически проверяющий с этим согласен — он вынес то же самое отдельным пунктом в новые проблемы.
3. **Лимитер.** Проверяющий — OPEN, скептик — PARTIAL. **Сильнее скептик:** основной сценарий (перебор одного аккаунта) реально отбивается и закреплён спекой `hardening.test.ts`; дыры настоящие, но «правка не работает» — неверно.
4. **Спека «корзина переживает вход».** Проверяющий заявил, что её нет. Скептик показал `tests/auth.test.ts:123` — при перестановке `mergeCarts` и `closeSession` спека покраснеет. **Скептик прав, замечание отклоняется**; остаётся меньший пробел — ветка `mine === null` не покрыта.
5. **Охранник `if (path === DOWN)`.** Проверяющий: без него был бы 508. Скептик: вложенный рендер не падает и второго rewrite не порождает, 508 сам по себе не случился бы. **Сильнее скептик** — он проследил `rewrites/handler.js`.
6. **`CLAUDE.md` и `getStaticPaths`.** Проверяющий: правила в тексте нет. Скептик: правило на строке 423, помечено неприменимым после перехода на SSR. **Сильнее скептик** (указал строку).
7. **Серьёзность двух пунктов.** `known=false` навсегда: major против minor — скептик обосновал снижение (SSR тоже глотает отказ, нужен именно переходный отказ). `Map` лимитера: major против minor — скептик указал, что база выдохнется раньше памяти.

## Вывод

Работу по ревизии выполненной считать нельзя: из заявленного закрыта примерно половина, две правки дали регрессии (поиск отвечает 200 вместо 503, кнопка сравнения на дорисованных карточках делает обратное написанному), отчёт `17-audit-fixes.md` в трёх местах расходится с кодом, а поверх всего вскрыта новая критичная утечка пароля в журнал через битый JSON.
