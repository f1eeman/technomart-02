## 1. Подтверждено и требует правки

### Критично

**1.1. Страница 503 не работает ровно тогда, когда нужна**
`web/src/components/header.astro:5`, `web/src/server/api.ts:13`, `web/src/middleware.ts:45`
Шапка и подвал на каждой странице зовут `cartOf` без `.catch` (у соседнего `meOf` catch есть), а рисуются они уже в потоке — после того, как статус и `<head>` ушли клиенту.
_Отказ (замерено на живом стенде с мёртвым API):_ главная, /about, /login, /profile, /register, /reset, /restore отдают **HTTP 200** с обрезанным телом и словами «Internal server error»; /cart и /compare отдают 503, но тело тоже обрывается на `<body>` — блока «Магазин временно недоступен» нет. Поисковик индексирует пустышку как рабочую страницу.
_Что сделать:_ `cartOf` — `.catch(() => пустая корзина)`, как у `meOf`; страницу 503 строить без шапки, ходящей в API (или отключить стриминг, чтобы middleware успел подменить статус).

**1.2. Ключ сессии уходит в логи открытым текстом**
`api/src/logger.ts:9`, `api/src/app.ts:27`
`redact` закрывает только входящую cookie; `pino-http` штатным сериализатором пишет все заголовки ответа, включая `set-cookie`, на уровне `info`.
_Отказ:_ после каждого входа/регистрации/первого добавления в корзину в журнале лежит `sid=<ключ>`. В базе — только sha256, то есть **лог сильнее базы**: любой с доступом к журналам (админ, сборщик логов, выгрузка в облако) ходит под покупателем, читает заказы, отменяет их.
_Что сделать:_ свой сериализатор `res` (только `statusCode`) либо redact пути `res.headers["set-cookie"]`; закрыть спекой.

**1.3. На дорисованных карточках каталога кнопки мертвы**
`web/src/scripts/catalog.ts:267`, `web/src/scripts/cart.ts:29`, `web/src/scripts/compare.ts:18`
Слушатели вешаются один раз по существующим узлам; клоны из `<template>` получают только `data-*`. Делегирования нет нигде.
_Отказ:_ каталог → «2» в пагинации или любой цвет фильтра → «В корзину» и «Добавить к сравнению» не делают ничего. Карточки, уцелевшие от прошлой выдачи, работают, поэтому выглядит как «иногда кнопка не нажимается».
_Что сделать:_ один делегированный слушатель на документ по `closest('[data-cart-add]')`.

### Серьёзно

**1.4. Пустая выдача каталога = полностью мёртвая страница**
`web/src/pages/catalog/[category].astro:78,111`, `web/src/scripts/catalog.ts:119,232,427`
`<template>` рисуется только `sample !== null`, а `initCatalog()` без шаблона выходит до навешивания обработчиков. Плюс «Вперёд» не ограничена сверху, а пустота определяется по `total`, а не по `items`.
_Отказ:_ сдвинул ползунок так, что ничего не подошло (или нажал «Вперёд» с последней страницы) — карточек ноль, подсказка «ничего не подошло» спрятана, пагинация без текущего номера, и **ни фильтр, ни ползунок, ни сортировка больше не работают**. Выход — только правка адреса руками.
_Что сделать:_ рисовать шаблон всегда; пустоту считать по `items.length`; подрезать номер страницы по `totalPages` и повторять `syncUrl()` после ответа.

**1.5. Оформление заказа: проверки вне транзакции**
`api/src/orders/service.ts:57,70,121`
В транзакции только запись; чтение корзины и расчёт суммы — снаружи, без блокировки.
_Отказ:_ двойной клик «Оформить» (кнопка не блокируется) — вторая транзакция падает на `cart.delete` по удалённой строке, P2025 → **500 вместо обещанного PRD 409**. Заказ при этом уже оформлен. Второй сценарий: товар, положенный в соседней вкладке между чтением и удалением, пропадает без сообщения.
_Что сделать:_ чтение и расчёт внутрь `$transaction` с `SELECT … FOR UPDATE`, либо ловить P2025 и отдавать 409.

**1.6. После 409 «сумма разошлась» покупатель заперт**
`web/src/scripts/cart.ts:267`
В `catch` результат `api.cart()` выбрасывается — `take()` не зовётся, сумма в сторе прежняя. Сервер при этом присылает свежую корзину в `details`, её игнорируют.
_Отказ:_ цена изменилась → 409 → в модалке та же сумма → повторное «Оформить» шлёт тот же `expected` → снова 409. Бесконечно, до перезагрузки страницы.
_Что сделать:_ добавить в стор `refresh()` через `take()` и звать его в catch (проще — брать корзину из тела 409).

**1.7. Корзина: ответ сервера затирает более свежий клик**
`web/src/scripts/cart-store.ts:47`, `web/src/scripts/cart.ts:161`
`take()` применяет любой промежуточный снимок, поколения нет; шаг «+» считается от значения в поле, которое этот снимок откатывает.
_Отказ:_ три быстрых «+» на товаре с количеством 1 → на сервере 3 вместо 4, плюс видимый откат числа.
_Что сделать:_ применять снимок только когда очередь пуста (как сделано поколениями в каталоге).

**1.8. Корзина мигает «пусто» и остаётся пустой при ошибке**
`web/src/scripts/cart-store.ts:29,71`, `web/src/scripts/cart.ts:277`
Стор стартует пустым и рассылает это слушателям немедленно, до первого ответа.
_Отказ:_ при любой загрузке /cart отрисованная сервером корзина мгновенно заменяется на «В корзине пусто» и возвращается через 20–200 мс. Если `api.cart()` ответил ошибкой (или перенос старого localStorage долго шлёт запросы) — покупатель видит пустую корзину при непустой, и счётчик в шапке обнуляется.
_Что сделать:_ сеять стор SSR-снимком либо не рассылать состояние до первого ответа.

**1.9. Перенос старого localStorage теряет или задваивает корзину**
`web/src/scripts/storage-move.ts:40-45`
Ошибка каждого `addToCart` глотается, а ключ `cart` удаляется безусловно в конце.
_Отказ:_ API не отвечает в момент первой загрузки — старая корзина стёрта и на сервер не попала. Обрыв на середине (закрыли вкладку, две вкладки разом) — перенесённые позиции задваиваются.
_Что сделать:_ снимать ключ сразу после чтения; при провале возвращать строки назад.

**1.10. Маска телефона кладёт в заказ чужой номер**
`web/src/scripts/phone-mask.ts:172`
На фокусе в буфер национальных 10 цифр кладётся код страны `'7'`, а вставка режет хвост.
_Отказ:_ покупатель кликает в поле, печатает 10 цифр — уходит `+77926000000`: лишняя семёрка и **потерянная последняя цифра**. Проверка «меньше 10 цифр» проходит. Тесты не ловят, потому что используют `fill()`.
_Что сделать:_ на фокусе буфер не трогать, префикс показывать отдельно.

**1.11. При входе не закрывается прежняя сессия покупателя**
`api/src/routes/auth.ts:69-77`
Ветка закрытия есть только для `guest.userId === null`. Отчёт задачи 11 обещает обратное.
_Отказ:_ общий компьютер, A вошёл и не вышел, B входит поверх — строка сессии A остаётся живой 30 дней и продлевается при каждом обращении. Кто снял её ключ — ходит под A. «Выйти» закрывает только текущую.
_Что сделать:_ `closeSession(guest.id)` вынести из условия слияния корзин.

**1.12. Битая cookie закрывает магазин навсегда**
`api/src/session/cookie.ts:28`
`decodeURIComponent` без try/catch на каждом обращении к сессии.
_Отказ:_ в браузере оказывается `sid=%E0%A4%A` (соседний поддомен, прокси, ручная правка) — URIError → 500 на каждом запросе → фронт показывает 503 на любом адресе. Сама cookie не сбрасывается: магазин закрыт, пока покупатель не очистит данные сайта.
_Что сделать:_ при URIError считать cookie отсутствующей и поставить свежую.

**1.13. Нет ограничения частоты ни на одном эндпоинте**
`api/src/app.ts:26-48`
Ни лимитера, ни зависимости. Каждый вход считает scrypt N=16384 (~16 МБ) — даже для несуществующего адреса.
_Отказ:_ перебор паролей по словарю без единой помехи; параллельные запросы на /login занимают пул libuv и ядра, живые покупатели упираются в страницу 503. Регистрация ещё и прямо сообщает, занят ли адрес.
_Что сделать:_ лимитер перед `/api/auth` (по IP и по нормализованному e-mail), 429 + Retry-After.

**1.14. Любой анонимный запрос заводит сессию на 30 дней**
`api/src/routes/cart.ts:65-78`, `api/src/routes/orders.ts:50-57`
Сессия открывается даже перед заведомым отказом («корзина пуста» → 409) и на `DELETE` несуществующего товара (заодно создаётся пустая корзина).
_Отказ:_ цикл POST /api/orders без cookie — тысячи строк `sessions` в секунду, живут месяц. Уборка чистит только по `expiresAt`.
_Что сделать:_ открывать сессию только на успешном POST /items; уборке дать порог по `seenAt`.

**1.15. Поиск падает в 500 на адресе, который набирает покупатель**
`web/src/pages/search.astro:10`, `api/src/routes/search.ts:9`
Вызов без `catch`; API режет запрос на 200 знаках и отдаёт 400, а `unreachable()` считает отказом только ≥500. У поля поиска нет `maxlength`. Страницы 500 в проекте нет вовсе — покупатель видит голое «Internal Server Error».
_Что сделать:_ обрезать запрос до 200, поставить `maxlength`, ловить 400 → пустая выдача. Заодно завести `500.astro`.

**1.16. Ошибки прокси не обрабатываются**
`web/src/middleware.ts:39`
Вызов `proxy()` стоит до `try/catch`, внутри — голый `fetch`.
_Отказ:_ API перезапускается, покупатель жмёт «В корзину» — прокси падает, Astro отдаёт не-JSON, клиентский `ask()` делает `response.json()` до проверки `ok` и получает SyntaxError вместо ApiError: ни одно заготовленное сообщение не показывается.
_Что сделать:_ обернуть прокси, отдавать 502/503 в формате `{"error":{...}}`; в `ask()` разбирать тело через try/catch.

**1.17. `unreachable()` ловит любой TypeError**
`web/src/middleware.ts:10-13`
Обычная программистская ошибка во фронтматтере (обращение к полю `undefined`) — тоже TypeError.
_Отказ:_ настоящая поломка маскируется под «магазин временно недоступен» с кодом 503 и Retry-After; поисковику уходит «зайдите позже» вместо «сломано».

**1.18. OpenAPI не описывает ни одного тела запроса**
`api/src/openapi/document.ts` (`grep -c requestBody` → 0)
Контракт держит только ответы; все тела во фронте написаны руками. Плюс типы `web/src/types/api.d.ts` генерируются вручную (`yarn api:types`) и нигде не сверяются в CI.
_Отказ:_ переименовали `expected` в API — `astro check` чист, zod молча выбрасывает неизвестное поле, **защита «сумма разошлась → 409» перестаёт работать**, узнаём по жалобе.
_Что сделать:_ добавить `requestBody` из тех же zod-схем; в сборку/CI — шаг «перегенерируй и убедись, что diff пуст».

**1.19. Браузерные тесты не видят живого API там, где семантика разная**
`web/tests/mock-api.mjs:446`, `web/tests/pages.spec.ts`
Мок ищет подстрокой и складывает поисковый текст из `categorySlug`, API — морфологией и по **названию** раздела.
_Отказ:_ спека «на «зарядка» ничего не нашлось» зелёная только на моке — в фикстурах слово «зарядки» встречается 5 раз, и русский стеммер их подтянет. Обратно: поломка живого поиска прогон не уронит.
_Что сделать:_ привести мок к семантике `search-text.ts` либо снять точные числа с моковых спек и проверять поиск только интеграционно.

**1.20. Персональные страницы без запрета кэширования**
`web/` (нет ни одного `Cache-Control` в `src/`), `web/docs/deploy.md:109`
Документ обещает `no-cache` на страницах — в коде этого нет; `Vary: Cookie` нет тоже; у ответов `/api/*` нет `no-store`.
_Отказ:_ любой кэширующий слой перед сайтом (CDN, proxy_cache, корпоративный прокси) отдаст чужую корзину и чужое состояние входа другому посетителю.
_Что сделать:_ `Cache-Control: private, no-store` + `Vary: Cookie` на HTML-ответы Node и на `/api/*`.

## 2. Опровергнуто (проверено, не дефект)

- **Поиск теряет фрагменты внутри длинных слов** — арифметика в находке считала `similarity`, а `<%` это `word_similarity`: «коптер» против «квадрокоптер» даёт ≈0.71 > 0.6, квадрокоптеры находятся. Остаётся узкий хвост (фрагмент из середины слова) — nit.

Про ширину полного снимка говорит `docs/tests.md` и велит сверять каталог снимком окна. Вёрстка в порядке: высоты 2830 и 2035 совпали с оригиналом до пикселя.

## 5. Чего ревизия не проверяла (слепые зоны)

- **Гонки не воспроизводились.** Двойное оформление, параллельные «+», одновременный вход в двух вкладках, `mergeCarts` с обрывом — разобраны по коду, но не запускались. Конкретно ответ Prisma на номер заказа >int4 (500 или пусто) чтением не устанавливается.
- **Тайминги не мерились.** Разница времени ответа на «нет покупателя» / «неверный пароль» и на `/restore` известного/неизвестного адреса выведена из кода, а не из замеров. Стоимость scrypt под нагрузкой тоже не мерилась.
- **Нагрузки и объёмов не было.** Рост `sessions`/`carts`, отсутствие индексов под FK, seq scan поиска без триграммного индекса — оценены на 38 товарах и пустых таблицах.
- **Прод-контур не трогали.** TLS, nginx, редиректы, кэширующий слой, `X-Forwarded-Proto`, выкладка образом, cron для `db:sweep` — только по документам. Обе описанные схемы выкладки (по deploy.md и через compose) вживую не прогонялись.
- **Почта не отправлялась.** Реальный SMTP, авторизация, `SMTP_SECURE`, доставка письма сброса и переход по ссылке из письма не проверялись — только Mailpit-конфигурация на бумаге.
- **Браузер один.** Прогон в headless Chromium на 1440×900; Safari (в т.ч. лимит `replaceState`), Firefox, мобильные, реальные пользовательские сценарии мышью — нет. Спящий CSRF на `/logout` с включённым prefetch не проверялся.
- **Попиксельная сверка с оригиналом выполнена по высоте, не по разности PNG.** Каталог полным снимком сверить нельзя (ширина 3800), окном — не снимали.
- **Не ревизовались вовсе:** доступность (a11y), производительность фронта (LCP/CLS), SEO кроме карты сайта, тексты и типографика кроме одного найденного слипания, восстановление после сбоя БД, резервное копирование, третий этап (админки нет ни одного маршрута).
