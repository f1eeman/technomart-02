# Отказ сервера и проверки

Status: ready-for-agent
PRD: .scratch/backend/PRD.md

**Страница «магазин недоступен».** Если API или база не отвечают, сайт отдаёт 503
на вёрстке существующей 404: шапка, подвал, одна фраза. Поисковик по 503 страницу
из индекса не выбрасывает — в отличие от 200 с пустым списком.

**Два набора проверок.** В `device-api` — интеграционные тесты по тестовой базе:
выдача, границы цены, поиск, формат ошибок. Во фронте Playwright перехватывает
`/api` и отдаёт фикстуры, поэтому десять существующих спек остаются быстрыми и не
требуют Postgres.

## Приёмка

- Погашенный API даёт 503 и человеческую страницу, а не стек.
- `yarn test:browser` проходит без поднятой базы.
- Прогон интеграционных тестов создаёт и сносит свою базу сам.

## Comments

**Сделано.** Страница отказа и два независимых набора проверок.

**503.** `src/middleware.ts` ловит недоступность API (ошибка сети или 5xx от
него) и отдаёт страницу «Магазин временно недоступен» с кодом 503 и заголовком
`Retry-After`. Вёрстка — по образцу существующей 404. Проверено на живой связке:
с погашенным контейнером API раздел отвечает 503 и человеческой страницей,
главная по-прежнему 200 (она в API не ходит), мусорный адрес — 404.

Попутно в тот же middleware добавлено **проксирование `/api` и `/uploads`** на
`API_BASE`. В бою это делает nginx, но без прокси клиентский `fetch('/api/…')`
некуда идти в `yarn dev` и в тестах.

**Браузерные тесты — без базы.** `playwright.config.ts` поднимает два сервера:
`tests/mock-api.mjs` с фикстурами (`tests/fixtures/catalog.json` — копия сида) и
сайт с `API_BASE`, направленным в мок. Мок повторяет контракт: выдача с фильтром
и страницами, весь каталог, товар по slug, сводка разделов, границы цены, поиск
по подстрокам. 62 спека проходят за полминуты и не требуют ни Postgres, ни
`device-api`.

Три спека пришлось поправить, и одна правка вскрыла настоящий дефект:

- проверка «в разметке 12 карточек» устарела — сервер отдаёт четыре;
- две проверки читали выдачу сразу после клика, до ответа сервера — переведены
  на `expect.poll`;
- **пустая выдача не объяснялась словами при серверной отрисовке**: фраза и
  пагинация переключались только скриптом. Теперь их состояние ставит сервер.

**Интеграционные тесты API.** `device-api/tests` на `node:test`: поднимают
приложение в том же процессе и бьют по нему настоящими запросами. База своя —
`device_test` создаётся, получает миграции и сид, после прогона сносится.
15 тестов: состав и число страниц, фильтр по цвету с Bluetooth, сортировка по
цене в обе стороны, сортировка по типу русским алфавитом, страница за пределами
выдачи, границы цены по всему разделу, морфология и опечатки в поиске, четыре
вида отказов и health.

`docs/tests.md` переписан в части запуска: откуда берутся данные для спек, почему
живой API им не нужен и как поднимать сайт под снимки.
