# Аккаунты: регистрация, вход, выход

Status: ready-for-agent
PRD: .scratch/backend/PRD.md

Вход по e-mail и паролю. Пароль хранится хешем (argon2id либо bcrypt), в логи не
попадает никогда. Подтверждение почты не требуется: зарегистрировался — вошёл.

Сессия — строка в базе, в cookie только её ключ. «Запомнить» из свёрстанной формы
даёт 30 дней, без галочки cookie живёт до закрытия браузера. Выход удаляет строку
сессии, а не только cookie.

**При входе корзины складываются**: гостевая и та, что лежала в аккаунте. У
одинаковых товаров берётся большее количество.

Страница `/register` верстается по образцу `/login`: те же поля плюс повтор
пароля. Ссылки на неё — из модалки входа и со страницы входа. Модалка входа
начинает проверять пароль по-настоящему.

Правило «вход ничего не защищает» отменяется — `CONTEXT.md` и `CLAUDE.md`
правятся в этой же задаче.

## Приёмка

- Неверная пара «почта — пароль» отвечает одинаково для несуществующего адреса и
  неверного пароля: по ответу нельзя перебрать чужие адреса.
- Повторная регистрация на занятый адрес — 409, а не падение уникального ключа.
- После выхода прежний ключ сессии не пускает: ответ 401, а не молчаливый вход.
- Гость с корзиной входит — товары складываются, ничего не потеряно.

## Comments

**Сделано.** Вход перестал быть обращением и стал входом.

`users` с уникальным e-mail, паролем-хешем и именем. Хеш — scrypt из
`node:crypto`: ни одной новой зависимости, параметры (N=16384, r=8, p=1) и соль
лежат в самой строке, сравнение — `timingSafeEqual`.

Эндпоинты `/api/auth`: регистрация, вход, выход, «кто вошёл». Регистрация сразу
пускает внутрь. Вход отвечает **одинаково** на незнакомый адрес и на неверный
пароль — и по коду, и по телу, и по времени: для несуществующего покупателя всё
равно считается хеш-заглушка, иначе адреса перебирались бы по задержке ответа.

**Слияние корзин** — в момент входа: строки гостевой корзины переносятся в
корзину аккаунта, у совпавших товаров берётся большее количество. После слияния
гостевая сессия закрывается и открывается новая, уже с владельцем: так вход не
наследует чужой ключ сессии.

Фронт: `session.ts` переписан на API, модалка входа и `/login` спрашивают e-mail
(поле было «Логин»), появилась страница `/register` по образцу `/login` со
ссылками в обе стороны. Имя вошедшего и признак `data-session` ставит сервер, а
не скрипт после загрузки.

Проверено:

- семь интеграционных тестов аккаунтов, всего в API 31;
- 62 браузерных спека зелёные: хелпер тестов заводит настоящий аккаунт, мок умеет
  регистрацию, вход и выход;
- на живой связке регистрация проходит, повторная даёт 409 с человеческой
  фразой.

**Две ловушки, стоившие прогона.** Тестовые адреса были кириллицей — браузер не
пускает такие в `type="email"`, и форма молча не отправлялась. И мок выдавал
предсказуемые ключи сессий, поэтому параллельные воркеры перетирали друг другу
вход; теперь ключ случайный.
