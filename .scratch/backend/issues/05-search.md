# Поиск: морфология и опечатки

Status: ready-for-agent
PRD: .scratch/backend/PRD.md

Поиск переезжает в Postgres: `tsvector` с русской морфологией по названию и
описанию плюс `pg_trgm` на похожие слова. Это закрывает открытый вопрос
владельца из `CONTEXT.md`: «квадракоптер» должен находить квадрокоптеры, «часы» —
находить «часов».

Результаты ранжируются: точные совпадения выше похожих.

## Приёмка

- Запросы из `CONTEXT.md` («квадракоптер») возвращают товары.
- Пустой запрос ведёт себя как раньше и не отдаёт весь каталог случайным
  порядком.
- Запись `CONTEXT.md` в разделе «Не выяснено» обновлена: вопрос закрыт.

## Comments

**Сделано.** `GET /api/search?q=…`.

У товара появилась колонка `search_text`: название, описание, тип, название
раздела и характеристики — тот же текст, что собирал `searchTextOf` во фронте, и
так же нормализованный (нижний регистр, «ё» → «е»). Заполняется при записи
товара, то есть сидом, а позже админкой.

Два индекса GIN: по `to_tsvector('russian', search_text)` — морфология, и по
`search_text gin_trgm_ops` — похожие слова. Запрос берёт строки, которые прошли
полнотекстовый поиск **или** похожи по триграммам, и сортирует: сначала точные
совпадения, потом по `ts_rank`, потом по `word_similarity`. Порог похожести —
умолчание `pg_trgm`, 0.6; «квадракоптер» против квадрокоптеров даёт 0.63.

**Расширение прежнего решения.** Серверу понадобились названия разделов, а не
только их `slug`: без них «умные часы» не находили бы раздел, как находил фронт.
Названия лежат константой в `src/catalog/categories.ts` — в базу разделы
по-прежнему не едут.

Проверено на десяти запросах против нынешнего поведения фронта:

- «квадрокоптер» — 6 товаров, ровно те же, что у фронта
- «квадракоптер» — 6 товаров, а фронт находил ноль
- «часы» — 13 против 5 у фронта: подтянулись товары, где в описании «часов»
- «селфи палка» — 12, то же самое
- «шлем», «алюминий» — совпало
- пустой запрос и «бензопила» — пусто

Ни на одном запросе не потеряно ничего из того, что находил фронт: поиск только
расширился.

`CONTEXT.md` обновлён: в глоссарии появился термин **Поиск**, вопрос владельца о
нестрогом совпадении убран из «Не выяснено» — он закрыт.

**Заметка на будущее.** Прерванная по таймауту `prisma migrate dev` оставляет за
собой сессию, которая держит advisory lock, и следующая миграция падает с
`P1002`. Лечится снятием зависшей сессии — искать в `pg_stat_activity` по
`DROP DATABASE IF EXISTS "prisma_migrate_shadow_db…`.
