# Правки по ревизии

Status: ready-for-human
PRD: .scratch/backend/PRD.md

Отчёт ревизии — `.scratch/backend/audit.md`. Здесь то, что по нему сделано, и то,
что осознанно оставлено.

## Сделано

**Критичное.**

- Страница «магазин недоступен» действительно показывается: шапка и подвал больше
  не роняют страницу (`cartOf` ловит отказ, как и `meOf`), а стриминг ответа
  выключен — без этого middleware не успевал подменить статус. Проверено с
  погашенным API: каталог, товар, корзина и поиск отвечают 503 с настоящей
  страницей, а главная и вход — 200, потому что им API не нужен.
- Ключ сессии больше не пишется в журнал: настройка `pino-http` вынесена в
  `httpLogger`, ответ сериализуется одним `statusCode`. Закрыто спекой
  `tests/logging.test.ts`.
- Кнопки «В корзину» и «Добавить к сравнению» работают на дорисованных карточках:
  клики делегированы документу. Закрыто спекой про вторую страницу каталога.

**Серьёзное.**

- Пустая выдача больше не замораживает каталог: образец карточки рендерится
  всегда, пустота считается по составу, номер страницы подрезается.
- Оформление проверяет состав внутри транзакции и отвечает 409 вместо 500, если
  корзина ушла из-под ног.
- После 409 «цена изменилась» модалка берёт свежий итог — цикл разорван.
- Корзина не теряет быстрые клики (снимок применяется только при пустой очереди)
  и не мигает «пусто» до первого ответа.
- Перенос старого `localStorage` не теряет корзину при отказе сети: непереехавшие
  строки возвращаются в хранилище.
- Маска телефона больше не подставляет лишнюю семёрку и не режет последнюю цифру.
  Закрыто спекой с посимвольным вводом.
- При входе закрывается прежняя сессия, битая cookie не роняет запросы, появился
  лимит попыток на `/api/auth`, сессии не заводятся ради отказа.
- Сброс пароля гасит все выданные ссылки и защищён от повторной отправки одной.
- Поиск не падает на длинном запросе, у поля появился `maxlength`.
- Прокси `/api` отдаёт 502 в общем формате вместо мусора, не тащит лишние
  заголовки и не кэшируется.
- Тела запросов описаны в OpenAPI, клиент фронта типизирован ими же; в схеме
  появилось описание cookie-сессии.
- Заголовки кэша ставит сайт: персональные страницы — `private, no-store`,
  обычные — `no-cache`, всё с `Vary: Cookie`.
- Восстановлен триграммный индекс, снесённый миграцией сессий, и объявлен в
  `schema.prisma` — следующий `migrate diff` его не тронет. Добавлены индексы под
  внешние ключи.
- Уборка чистит гостевые корзины и просроченные ссылки на сброс.

**Документы.** ADR 0003, 0007 и 0008 помечены статусом, `deploy.md` знает про
почту, образы, уборку и заголовки кэша (включая то, что `/api` в бою идёт мимо
Node), `docs/tests.md` — про мок, число спек и **расхождение семантики поиска**,
README API — про восемь таблиц, адреса и переменные почты, `CLAUDE.md` и
`CONTEXT.md` — про четыре модалки, четыре ключа хранилища и сравнение.

## Второй заход: что нашла проверка исправлений

Отчёт — `.scratch/backend/audit-verify.md`. Своими же правками было внесено пять
огрехов, все закрыты:

- поиск глотал любой отказ API и отвечал «ничего не нашлось» вместо 503 — теперь
  ловится только 400;
- дорисованная карточка каталога не знала, что товар уже в сравнении, и кнопка
  обещала добавить, а убирала;
- прямой заход на `/503` шёл мимо заголовков кэша, а `/uploads` получал
  `no-store` вместо часового кэша от API;
- подстановка в форму входа читала ключ `login`, который больше никто не пишет, —
  теперь берётся `email`;
- `verifyPassword` доверял параметрам из строки хеша: вырожденный хеш пускал кого
  угодно. Параметры проверяются на разумность, длина ключа фиксирована.

Сверх того закрыто: письмо о сбросе больше не держит ответ (и не выдаёт
существование адреса временем), отправка не роняет процесс, лимитер получил своё
ведро на каждую ручку и общий потолок по адресу, включён `trust proxy`, коды
`unauthorized` и `too_many_requests` появились в схеме ошибки, тела запросов
описываются как вход, первая загрузка корзины и `refresh` идут через очередь,
отказ первого запроса больше не оставляет корзину «мёртвой», двойной клик по
«Оформить» не уходит дважды.

Спеки добавлены на страницу отказа (мок притворяется сломанным по cookie
`boom=1`), на подпись кнопки сравнения после перерисовки и на просрочку ссылки
сброса — прежняя спека была тавтологичной.

## Осталось после второго захода

Проверка исправлений назвала это, и оно **не** закрыто:

- **Страницы 500 нет.** Ошибка, не связанная с недоступностью API, отдаёт голое
  «Internal Server Error». Отдельная страница — отдельная работа.
- **В `astro dev` подмена ответа на 503 не работает**: отключение стриминга —
  опция адаптера, а в разработке адаптер не участвует. Записано в `docs/tests.md`.
- **`askReset` не гасит прежние ссылки** при выдаче новой: живыми остаются все
  выданные за час. Гасит их только успешный сброс.
- **Лимитер живёт в памяти процесса.** При нескольких экземплярах API счёт у
  каждого свой, окно фиксированное. Для витрины достаточно, для боя нужен общий
  счётчик.
- **Занятый адрес по-прежнему виден** по 409 на регистрации. Спрятать его можно
  только ценой «письмо отправлено, проверьте почту» вместо честного ответа.
- **Корзина не синхронизируется между вкладками** и после возврата из bfcache:
  «+» во второй вкладке может воскресить удалённый в первой товар.
- **Проверка состава при оформлении — без `FOR UPDATE`.** Окно гонки сузилось до
  одной транзакции, но полностью не закрыто.
- **PATCH и DELETE корзины без cookie отвечают 200 с пустой корзиной** — протухшая
  сессия неотличима от пустой.
- **Сверки «перегенерируй типы и убедись, что diff пуст» нет**, потому что нет и
  CI. Пока это делается руками перед сборкой.
